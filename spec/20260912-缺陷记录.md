# 缺陷记录 · 2026-09-12

工作空间 / 视图 / 标签相关功能的 8 项缺陷。改动集中在 `src/frontend` 与 `style/main.css`。

> 验证状态：`cargo check`（ssr 与 wasm32·hydrate）、`cargo leptos build`（ssr + wasm-bindgen）、
> `cargo test`（78 项）、`cargo clippy`（26 条 warning，均为改动前既有）通过。
> **已做浏览器实测**：headless Chromium 登录后跑通 25 项断言（缺陷 1–6 各覆盖到）+ 缺陷 7（5 项）
> + 缺陷 8（5 项），全部通过；截图见 `/tmp/rodeo-verify/*.png`。真机视觉仍建议人工复核一遍。

## 1. 在工作空间的配置页没有返回按钮

- **现象**：进入 `/{slug}/settings` 后没有任何返回入口，只能改地址栏。
- **定位**：`src/frontend/pages/settings.rs`（设置页只有面包屑 + 标签页侧栏）。
- **修复**：面包屑左侧新增「返回工作空间」按钮（`ic_back`），点击跳 `/{slug}`。

## 2. 编辑标签，点击保存按钮，生效了，但是没有视觉上的反馈，应该让保存按钮变灰

- **现象**：标签定义表格里点「保存」后数据已落库，但按钮外观不变，无法判断是否保存成功。
- **定位**：`src/frontend/pages/settings.rs` 的 `schema_row`，保存按钮恒为可点。
- **修复**：为每行加入 `dirty` 状态（标题 / 枚举值 / 基础色 / 值色任一被编辑即置位），
  无改动时按钮 `disabled` 置灰。保存后整行按服务端数据重建，按钮自动回到灰态，即是「已保存」的反馈。
  置灰按钮仍沿用「行 hover 才显示」的样式，避免表格常驻一排灰按钮。
  - **浏览器实测时补漏**：首版只把「值色 swatch」接进了 `dirty`，同一个行内的**基础色** swatch
    （`settings.rs` 里另一个内联 `input type="color"`）漏接了。只改基础色时按钮依旧置灰、改动无法保存。
    已补 `dirty.set(true)`。

## 3. 新建视图时，「展示为列的标签」应该支持选择，而不是让用户输入

- **现象**：新建视图与视图配置弹窗都用「逗号分隔」的文本框收集列，用户填的是展示名（如「优先级」），
  服务端校验要求的是标签 `name`（如 `Priority`），填错即被拒绝（且当时是静默失败，见 4）。
- **定位**：`src/frontend/pages/workspace_main.rs` 两处弹窗；服务端校验见
  `src/service/view.rs` 的 `validate`（`列引用了不存在的标签`，已有测试覆盖）。
- **修复**：新增 `ColumnPicker` 组件——按工作空间已有的标签渲染可勾选 chip，产出 `name` 列表，
  从源头消除非法列名输入；两个弹窗共用。

## 4. 新建视图，配置条件，点击保存视图按钮没有反应，刷新页面后视图丢失

- **现象**：新建视图后配置条件，点「保存视图」无任何反应；刷新后视图/条件丢失。
- **原因**：两处叠加。
  1. `create_view` / `update_view` 的结果用 `if let Ok(..)` 承接，`Err` 被直接丢弃——
     弹窗内创建失败、筛选条上保存失败都不会有任何提示。
  2. 「展示为列的标签」是自由文本，填入的展示名无法通过服务端列校验，导致创建/保存整体失败（见 3）。
  两者叠加就表现为「点了没反应，刷新后什么都没有」。
  *以上为代码定位结论。浏览器实测确认了修复后的行为：服务端返回
  `列引用了不存在的标签: Priority` 时，错误直接显示在弹窗内（红字），弹窗不关闭、
  已填名称与已勾选标签都保留；`保存视图` 在无改动时置灰、改排序后解禁、保存成功后重新置灰。*
- **定位**：`src/frontend/pages/workspace_main.rs`。
- **修复**：
  - 弹窗内新增 `dialog_error`（页面级 `error` 渲染在遮罩之下，用户看不到），
    创建/配置失败直接在弹窗内提示，且失败时弹窗不关闭、保留已填内容。
  - 「保存视图」失败回写 `error`；成功则刷新 `saved_baseline`。
  - 新增 `saved_baseline`（query / 排序列 / 排序方向）与当前编辑态比较，
    无差异时「保存视图」置灰——挡掉无效提交，并让保存成功有可见反馈。

## 5. Entry 列表左上角不要固定显示「全部内容」，而是显示视图名称，如果是工作空间下的默认视图，则还是保持显示「全部内容」

- **现象**：面包屑与列表标题硬编码「全部内容」，切到任何视图都不变。
- **定位**：`src/frontend/pages/workspace_main.rs`（面包屑与 `.vhead h2`）。
- **修复**：标题与面包屑改为跟随 `active_view`——有选中视图时显示 `视图「{名称}」`，
  未选中任何视图时回退到 `默认视图「全部内容」`。
- **实测确认**：侧栏有视图时进工作空间会自动选中第一个（`load_views` 的既有逻辑），故
  「全部内容」只在**一个视图都没有的工作空间**里出现——已用一个空工作空间验证通过。
- **待确认**：当前没有「默认视图」实体（工作空间创建时只内置 Task/Bug 标签，不预置视图），
  所以回退文案只在侧栏一个视图都没有时出现。若希望每个工作空间显式预置一个名为「全部内容」的默认视图，
  需要另做（服务端建工作空间时播种 + 对已有工作空间补齐）。

## 6. Entry 详情全屏，编辑区高度太小，标签太宽，一行可以展示多个标签，每个标签可用边框包围形成一个整体，下部的按钮也太宽（将按钮移动到右上角）

- **现象**：全屏详情里富文本编辑区被压在约 220px；每个标签独占一行且控件拉满宽度；
  底部「全屏打开 / 保存 / 删除」被 `flex:1` 拉成等宽大按钮。
- **定位**：`EntryPanel`（`src/frontend/pages/workspace_main.rs`）、`LabelEditor`
  （`src/frontend/label_editor.rs`）、`style/main.css`。
- **修复**：
  - 三个操作按钮移入详情头部右上角的 `.dacts`，改为紧凑小按钮；底部按钮区删除。
  - 标签编辑器根节点加 `.lbledit`（flex-wrap），`.lblrow` 由「88px + 1fr 栅格行」改为
    带边框的 inline-flex chip，一行排多个标签块；控件宽度改为自适应。
  - 全屏浮层下让 `.editor` 吃掉剩余高度（`flex:1` + `min-height:240px`），
    富文本容器与 `.ql-container` 一并撑满，正文内部滚动。
- **影响面**：`EntryPanel` 与 `LabelEditor` 是共用组件，右侧详情面板和独立的
  `/{slug}/entry/{code}` 页面会一并套用新的标签 chip 样式。

## 7. 在详情里改了标签值，列表里的标签列不更新，一直显示「—」

- **现象**：在右侧详情面板给 Entry 加上「任务 = Open」，面板立刻显示 Open，但列表里
  「任务」列仍是「—」；配置了「任务」「缺陷」两列时两列都恒为「—」，看起来像标签根本没写进去。
- **定位**：`src/frontend/pages/workspace_main.rs` 的 `EntryPanel`。
- **原因**：`on_changed`（标签变更回调）只调了 `load(false)` 软重载**面板自身**的 labels，
  没有去动父组件的 `refresh` 信号；而列表数据来自父组件依赖 `refresh` 的 Effect。
  同一个组件里「保存」与「删除」都调了 `refresh.update(...)`，只有标签这条路径漏了。
  → 值其实早就落库了（`entry(code)` 查得到 `Task = Open`），只是列表不重查。
- **修复**：`on_changed` 里补 `refresh.update(|n| *n += 1)`。
- **实测**：改标签前「任务」列 `"—"` → 改后立刻 `"Open"`（修复前即使点侧栏视图也不刷新，
  因为重选同一个视图不改变任何依赖，Effect 不会重跑）。

## 8. 新建 Entry 时无法填写标签，只能先创建再进详情补

- **现象**：新建表单只有标题一个输入框，标签值只能等条目创建后到详情面板里补。
- **定位**：`src/frontend/pages/workspace_main.rs`（新建表单 `form.filters`）、`style/main.css`。
- **修复**：
  - 新增 `DraftLabel`（`name/title/value_type` + 文本、三态布尔信号）与 `LabelDraft` 组件：
    沿用 `LabelEditor` 的 `.lbledit`/`.lblrow` chip 外观，但只写本地草稿，不即时落库。
  - 打开表单时按当前工作空间的标签 schema 重建草稿行；「创建」时先 `create_entry`，
    再把非空草稿逐个 `set_labeling`（服务端 `createEntry` 只接收标题）。
  - 布尔用三态下拉「（未设置）/是/否」，而不是复选框——否则「未勾选」无法与「明确设为假」区分。
  - 空输入一律视为「本次不写这个标签」；单个标签写入失败会报出「条目已创建，但标签…写入失败」，
    不静默丢弃（沿用缺陷 4 的原则）。
- **实测**：填标题 + 任务=Open / 负责人=张三 / 工作量=5 / 评审=是 → 创建后服务端返回
  `Task="Open"`, `Owner="张三"`, `Effort=5`, `Review=true`，未填的缺陷/领域/迭代未写入。
