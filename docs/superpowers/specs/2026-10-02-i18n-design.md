# 国际化（i18n）实现设计

日期：2026-10-02
类型：架构变更（新子系统）

## 目标

让 Rodeo 的全部前端 UI 静态文案支持 6 种语言（中文、English、Português、Español、العربية），
并在标题栏提供语言切换入口。默认语言根据浏览器 locale 选择，未匹配时回退到英语。

不在范围内：
- 服务端消息（GraphQL 错误码、AI 摘要结果、用户生成的正文与评论）
- 邮件 / 通知模板
- 工作区、条目、标签、视图的 `name` / `title` / `description`（这些是用户数据）

## 设计原则

1. **沿用 `theme` 的形状**：与 `provide_theme`/`use_theme`/`localStorage` 的现有模式一致；
   不引入新的 crate（用户已确认内置方案）。
2. **字符串与逻辑分离**：JSON 文件 + `i18n!()` 宏，编译期嵌入；键名英文常量，运行时查表。
3. **SSR / Hydrate 对齐**：服务端读 `Accept-Language` 选语言 → 写 `<html lang>` 与 `<html dir>`；
   客户端首屏前用 `<head>` 内联脚本比照 localStorage，避免语言切换闪屏。
4. **RTL 支持**：仅 Arabic 是 RTL；在 `<html dir>`、`<body dir>` 上挂 `rtl`；布局调整交给 CSS。
5. **不破坏现有架构**：Leptos 上下文只向下传播，所以把 `I18nController` 在 App 层 `provide_context`，
   与 `ThemeController` 同一层。

## 核心模块：`src/frontend/i18n.rs`

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum Locale {
    Zh, En, Ja, Pt, Es, Ar,
}

impl Locale {
    pub fn as_str(self) -> &'static str { /* "zh"/"en"/"ja"/"pt"/"es"/"ar" */ }
    pub fn label(self) -> &'static str { /* "中文"/"English"/...*/ }
    /// 浏览器 navigator.languages 字符串 → Locale（接受 "zh-CN"/"zh"/"zh-Hans-CN" 等）。
    pub fn from_browser(s: &str) -> Option<Self>;
    /// Accept-Language 头解析 → Locale，按 q 值降序匹配。
    pub fn from_accept_language(header: &str) -> Option<Self>;
    pub fn is_rtl(self) -> bool { matches!(self, Self::Ar) }
}

#[derive(Clone, Copy)]
pub struct I18nController {
    pub locale: RwSignal<Locale>,
}

impl I18nController {
    pub fn set(&self, loc: Locale) { /* 写信号 + DOM + localStorage */ }
    /// 获取当前 locale 下 `id` 对应的字符串（id 是 `"namespace.key"` 形态）。
    pub fn t(&self, id: &'static str) -> &'static str;
    /// 格式化：替换 `{name}` 占位符。
    pub fn tf(&self, id: &'static str, args: &[(&str, &str)]) -> String;
}

pub fn provide_i18n(initial: Locale) -> I18nController { /* ... */ }
pub fn use_i18n() -> I18nController { /* ... */ }
```

### `i18n!()` 宏（`src/frontend/i18n_macros.rs`）

```rust
#[macro_export]
macro_rules! i18n {
    ($id:literal) => {{
        // 在组件 setup 阶段拿 I18nController，闭包形式让响应式重渲生效。
        let i18n = $crate::frontend::i18n::use_i18n();
        move || i18n.t($id)
    }};
    ($id:literal, $($name:literal = $val:expr),+ $(,)?) => {{ /* tf 形态 */ }};
}
```

调用方写法：
```rust
view! {
    <button>{i18n!("appbar.new_entry")}</button>
    <button>{i18n!("workspace.delete_confirm", name = name.as_str())}</button>
}
```

### 翻译表加载（`locales/{zh,en,ja,pt,es,ar}.json`）

```json
{
  "_meta": { "name": "中文", "dir": "ltr" },
  "appbar": {
    "new_entry": "新建 Entry",
    "new_view": "新建视图"
  },
  "login": {
    "title": "登录 Rodeo",
    "email": "邮箱",
    "password": "密码",
    "submit": "登录"
  }
}
```

每条字符串以 **中英对照基准** 写在 `en.json` 与 `zh.json` 中；其他三种语言的 JSON 文件由本
次任务一次性产出（葡萄牙、西班牙、阿拉伯翻译可外协或基于通用模板生成，缺失键必须回退到英文）。

JSON 用 `include_str!` 编译期嵌入：`const EN: &str = include_str!("../locales/en.json");`
通过 lazy `OnceLock<HashMap<&'static str, &'static str>>` 在第一次 `t()` 时构建。
构建不是性能瓶颈：键数 < 500，map 一次性构建 + 字符串全部静态。

## SSR / Hydrate 对齐策略

### 服务端（`src/app.rs::shell`）

```rust
fn resolve_initial_locale(parts: &HttpParts) -> Locale {
    // 1. URL query ?lang=xx-XX（方便手动测试）
    if let Some(l) = parts.url.query_param("lang") {
        if let Some(l) = Locale::from_browser(l) { return l; }
    }
    // 2. cookie rodeo_lang（用户上次选过）
    if let Some(c) = parts.headers.get("cookie").and_then(|v| v.to_str().ok()) {
        if let Some(l) = parse_cookie(c, "rodeo_lang") {
            if let Some(l) = Locale::from_browser(&l) { return l; }
        }
    }
    // 3. Accept-Language 头
    if let Some(h) = parts.headers.get("accept-language").and_then(|v| v.to_str().ok()) {
        if let Some(l) = Locale::from_accept_language(h) { return l; }
    }
    Locale::En
}
```

然后：
- `<html lang={locale.as_str()} dir={if locale.is_rtl() { "rtl" } else { "ltr" }}>`
- 在 App 层 `provide_i18n(locale)`
- 把 `localStorage.rodeo_lang` 在第一次响应里写一次（仅当 cookie 路径用得上），让客户端 hydrate 后不会跳

### 客户端（hydrate）

`hydrate()` 启动时（仅 wasm）：
1. 读 `localStorage.rodeo_lang` → 与 SSR 给的 locale 比较：不同则更新 `i18n.locale`
   并写 cookie（用 `<meta http-equiv="Set-Cookie">` 不行，靠 JS 设 `document.cookie`）。
2. 读 `navigator.languages` → 若 localStorage 没值且 SSR 给的是默认（en），用 navigator
   重新解析；解析到非默认则更新 locale。

### 防闪屏的 `<head>` 内联脚本（追加到现有 theme 脚本旁边）

```html
<script>
  (function(){
    try{
      var l = localStorage.getItem('rodeo_lang');
      var html = document.documentElement;
      if (l === 'zh' || l === 'en' || l === 'ja' || l === 'pt' || l === 'es' || l === 'ar') {
        html.setAttribute('lang', l);
        if (l === 'ar') html.setAttribute('dir', 'rtl'); else html.setAttribute('dir', 'ltr');
      }
    } catch(e) {}
  })();
</script>
```

顺序：theme 脚本先（决定色），lang 脚本紧跟（决定文字方向）。两段都跑在 HashedStylesheet 之前。

## AppBar 语言按钮

放在 `<ThemeButton>` **之前**，与主题按钮使用相同的 `.lang-btn` 样式（复用 `.theme-btn` 的几何与 hover 态）。
点击不直接切语言——弹一个下拉选单（与 AvatarMenu 同种 `:hover` / `:focus-within` 模式）：

```html
<div class="lang-menu">
  <button class="lang-btn" title={current_locale_label}>
      {current_language_icon_or_text}
  </button>
  <div class="lang-drop">
    {for loc in Locale::all() {
        <button class="lang-mi" on:click=move |_| i18n.set(loc)>
          {loc.label()}
        </button>
    }}
  </div>
</div>
```

按钮内显示当前 locale 的短码（"EN" / "中" / "日" / "PT" / "ES" / "ع")，
title 属性（hover tooltip）显示完整名称。

## CSS 调整（`style/main.css`）

- `.lang-btn` / `.lang-drop` / `.lang-mi`：复用 `.theme-btn` 的几何；hover 态与主题按钮对齐。
- `[dir="rtl"] .appbar-right`：`flex-direction: row-reverse`（保持顺序但视觉左右对调）。
- `[dir="rtl"]` 选择器覆盖：
    - `.wside`、`.timeline-icon`、`/login` 表单 → 文本 / margin / padding 用 `direction: rtl` 配合
      `text-align: right`；用 `html[dir="rtl"] .xxx` 前缀，**避免**把已有的具体像素值全部改写。
    - 仅做「必要适配」：左右边距翻转、行高键 hover 时图标位置。数据密集页 / workspace_main 拆对话框那侧的「文档全集」按现有 memory `data-pages-full-width` 保持。
- `[lang="ar"] body`：自动 `font-family` 走系统 Arabic fallback（Segoe UI / Tahoma / sans-serif）。

## 翻译表生成

**一次性工作量**：把 24 个前端文件里所有硬编码的中文字符串抽到 `locales/*.json`。
预计 200~400 条键（其中多数是按钮文字、列标题、提示）。

策略：
1. 人工写 `en.json` + `zh.json`（基准译本，与现状完全等价）。
2. ja.json / pt.json / es.json / ar.json：每个键基于英文 / 中文用翻译工具一次产出，
   再用 `xtask check-locales`（dev-only 工具二进制，不进 `make build`/`make check` 链路）
   校验「所有 locale 都有相同键集合」：缺键 panic-by-build 提早暴露。
3. 缺失键的兜底：`t()` 在 locale map 中找不到键时回退到 `en` map，仍读不到 → 返回键本身
   （开发时一眼能看出漏译；生产日志里 warn 一次而不是每次都打）。

## 风险与对策

| 风险                                                  | 对策                                                                 |
| ----------------------------------------------------- | -------------------------------------------------------------------------- |
| Hydrate mismatch：SSR 给 en，hydrate 后切到 zh，闪一下 | head 内联脚本按 localStorage 把 html lang/dir 提前对齐；再让响应式重渲  |
| RTL 下布局错位                                        | 仅做「必要适配」+ 仅在 `[dir="rtl"]` 下覆盖 margin/padding；不改像素值  |
| 翻译键拼写错误（typo 导致整页沉默）| `t()` 找不到时回退 `en`，再不行返回键名 + dev 日志 warn                |
| 漏译某 locale                                          | `tools/check_locales.rs` dev-only build script：CI 阶段 panic            |
| Accept-Language 头解析错误                            | 手写一个 30 行的解析器（q 值、language-range 通配），不引依赖           |
| 服务端 AppError / GraphQL 错误文案是中文              | **不改**——错误文案与 SSE 流是用户数据的一部分；统一翻译表不入服务端  |
| micro/中文小端                                          | 「小端」=「细节错误」（如 wrong 字节序、属性名），非本任务范围          |

## 不在范围 / 显式放弃

- URL 路由前缀（`/en/...` `/zh/...`）——会导致现有书签失效、登录跳转路径变长；先做 in-tree 简单版，
  后续若需要再加 I18nRoute。
- 服务端 GraphQL 错误码 / AI 摘要 / 用户内容的翻译——属于消息层与 i18n 解耦。
- 日期 / 数字 / 货币本地化（`Intl` API）——UI 主要显示 RFC3339 + 系统本地时间，已足够；
  阿拉伯语 / 日语数字如确有反馈再处理（每条用 `Intl.NumberFormat`）。
- 标签 / 视图 / 工作空间名字翻译——这些是用户数据，按现状反馈。
